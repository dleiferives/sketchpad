The ergonomic decisions that matter

  1. Pen draws; navigation belongs to a separate gesture. On a pen-enabled touchscreen, start with two-finger navigation and finger painting off. Treat single-finger actions as a preference. This reduces ambiguous contacts; it is not a claim of hardware palm rejection.
  2. Never wait to decide whether pen-down means drawing. Avoid a default pen long-press menu on the canvas. A barrel button, dedicated visible button or finger gesture should invoke alternate tools without delaying ink.
  3. Keep controls near the working hand, and readouts out from under it. Mirror the rail, offset feedback from the pointer, use generous hit targets, and retain a tap route for actions that otherwise require chords.
  4. Adjust one thing at a time. A puck should select size or opacity from the first deliberate movement, then retain that choice until release. Small diagonal drift should not change both.
  5. Temporary tools should return automatically. A held eyedropper/eraser returns on release; an explicit selected tool stays selected. The UI must make the distinction visible.
  6. Trackpads are not miniature touchscreens. Use the pan/pinch events the platform actually exposes. Do not promise raw two/three-finger taps on every trackpad or fight desktop window-manager gestures.

Canvas fingers navigate rather than paint. Touch history waits until all fingers lift, and pen contact suppresses that touch sequence. Trackpad pinch depends on the platform; raw touchscreen taps are not promised on trackpads. View rotation, radial menus, held E erasing and simultaneous off-hand modifiers are future options.

The design directions

A · Implemented

Rail + puck + navigation

A small discoverable rail, size/opacity puck with axis lock, color picker, favorite values, pen-only navigation, plus desktop drag shortcuts and touch pan/pinch/history.

Why: covers all three input setups and improves the most frequent actions first.

B · Future option

Cursor-local pen menu

A six-action menu for brush, eraser, color, picker, undo and pan. Start with tap-to-open/tap-to-select, then offer press-slide-release.

Why: useful for large displays and minimal chrome. Requires stable sectors and reliable capture.

C · Future hardware option

Off-hand modifier

A movable touch button for temporary erasing or sampling while the pen works. Include a clear lock state and a pen-only toggle.

Why: powerful with two hands. Needs simultaneous pen/touch testing on the actual device.

Implementation and validation boundaries

Atlas application tests cover portrait/landscape layout, pointer ownership, focus restoration, brush adjustment axis locking, touch navigation/history, cancellation and saved keyboard binding migration. Live mouse/keyboard checks cover the puck, Shift/O drags, Space-pan, help, focus, color, drawing, erasing and undo.

Physical pen pressure, touch concurrency and gesture feel still need actual hardware. Rotation, radial menus and pen barrel-button mapping were not added. Whole-project strict Clippy has existing too-many-arguments warnings in the GPU compositor; the changed application passes with that lint allowed.
